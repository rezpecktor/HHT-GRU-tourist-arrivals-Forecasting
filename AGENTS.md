# Repository Instructions

## Context

Academic research on monthly tourist arrival forecasting
using GRU and Empirical Mode Decomposition (EMD).

Primary notebook:
`GRU_BASE_AND_HTT_GRU_FIXED.ipynb`

## Objective

Improve code presentation without altering scientific
behavior, experiment results, or notebook structure.

## Non-Negotiable Rules

- Never execute Python, notebook cells, training, or tests
  unless explicitly authorized.
- Do not change algorithms, formulas, preprocessing,
  model architecture, hyperparameters, data splits,
  random seeds, or evaluation procedures.
- Do not rename variables, functions, classes, or files.
- Preserve cell order, cell IDs, metadata, execution
  counts, and stored outputs.
- Do not modify datasets, figures, or dependencies.
- Do not reformat the entire notebook or clear outputs.
- Do not install packages, commit, or push changes.
- Do not change README claims or research methodology
  as part of cosmetic cleanup.

## Cosmetic Editing

When explicitly authorized:

- Remove unnecessary emojis and decorative symbols.
- Simplify exaggerated or informal print messages.
- Improve redundant or overly verbose comments.
- Preserve the original language and technical meaning.
- Avoid changing docstrings, logging behavior, and
  strings used in calculations or programmatic checks.
- Follow CODE_STYLE.md.

## Workflow

1. Inspect the requested scope in read-only mode.
2. Report proposed changes before editing.
3. Wait for explicit approval.
4. Make only the approved, minimal changes.
5. Review source-level and notebook-level diffs.
6. Report anything that could not be verified.

If a change may affect behavior, do not make it.
